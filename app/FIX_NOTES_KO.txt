M-ALIGN v3.6.0 / 2026-11-13 / 메인 서버 지시형 키트 연동 + 값 저장·묶음 전송

작업 순서 (리치스태커 기준)
1) 기계 이동·작업 준비 → 2) 기계가 메인 서버에 준비 완료 → 3) 메인 서버가 키트에 작업 실시(start_job)
→ 4) 키트 1회 센싱·보정값 전송 → 5) 메인 서버가 기계 정보와 비교해 보정 반영
→ 6) 이동 확인 후 센싱 지시(sense) → 7) 다시 센싱·전송 → 8) 5로 (약 6회) → 9) end_job 후 메인 동작(하강·결합)

추가
- 보정장치 4대(코너별 고유 번호)를 1세트(키트 번호)로 묶어, 센싱 1회마다
  네 장치의 5헤드 측정값·추정 오차·보정값을 "묶음 1개"로 만듭니다.
- 묶음은 먼저 %LOCALAPPDATA%\MALIGN\Link\outbox.sqlite3 에 저장하고,
  link_config.json 의 server_url 이 있으면 메인 서버로 순서대로 전송합니다.
  서버가 꺼져 있으면 '전송 대기'로 남았다가 연결되면 자동 재전송합니다.
- 메인 서버 지시(start_job / sense / end_job / stop)는 전송 응답으로 받습니다.
  회차 수와 종료는 메인 서버가 정합니다. 키트는 측정·보고만 합니다.
- server_url 이 없으면 시뮬레이터 안의 내장 시뮬 서버가 메인 서버 역할을 합니다(6회).
- 시뮬레이터 '1회 작업 실행' = 작업 1건. 성공률 계산(반복 시험)은 전송하지 않습니다.
- 메인 서버 예제: server_example\malign_main_server.py (자동/수동 모드)

바뀌지 않은 것
- 시뮬레이터 계산(시드 2026·기준 가정·100회 = 성공 6/실패 94 동일), cases.sqlite3 경로·형식.

주의
- 완전 제거 시 전송 대기 중인 기록도 함께 삭제됩니다(관리 창 경고에 건수 표시).
- 실제 센서 연결부(하드웨어 어댑터)는 아직 없습니다. docs\전송_프로토콜.md 6절 참고.

M-ALIGN v3.5.4 / 2026-11-11 / Windows sqlite3 handle cleanup fix

증상
BUILD_EXE.cmd [3/4] 테스트에서 PASS 두 줄 출력 직후
TemporaryDirectory 정리 시 MALIGN_daily_YYYYMMDD.sqlite3 파일 WinError 32.

원인
- tests/test_backup_windows_regression.py 에서 `with sqlite3.connect(snap) as c:`
  사용. sqlite3 연결 컨텍스트 매니저는 트랜잭션만 종료하고 DB 핸들은 닫지 않음.
- 테스트 마지막까지 c 변수가 연결을 잡고 있어 Windows에서 임시 폴더 삭제 실패.
- tests/test_storage_location.py 의 기존 스냅샷 검사에도 동일 패턴 발견.

수정
- 두 테스트에서 `with contextlib.closing(sqlite3.connect(...)) as c:` 사용.
- test_no_sqlite_handle_leaks.py 추가: 원래 패턴이 재도입되면 빌드를 중단.
- BUILD_EXE.cmd 단계 3에 누수 방지 검사 추가.
- 실제 CaseBank 백업 구현은 원래 with closing(source/dest)로 핸들을 닫고 있었으므로 그대로 유지.
- 시뮬레이터 JS/HTML, Maxwell 21케이스, 성공률 조건, 사례 DB 경로, 제거 규칙은 변경하지 않음.

저장 데이터
사용자의 %LOCALAPPDATA%\MALIGN\CaseBank\cases.sqlite3 파일은 이 ZIP이나
빌드 스크립트가 삭제·초기화하지 않음. 기존 v3.5.3 ZIP도 롤백 가능.

주의
이 환경에서는 Windows 3.13 및 PyInstaller 산출 EXE의 실제 실행 여부 확인 불가.
사용자 Windows PC에서 BUILD_EXE.cmd 실행 후 3/4 테스트 완료 및 4/4 생성 여부 확인.
